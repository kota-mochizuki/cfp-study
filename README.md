# CFP 配信講義（lectures ブランチ）

CFP Study アプリ（https://kota-mochizuki.github.io/cfp-study/）の「講義」画面に表示する講義データです。
アプリはこのブランチの `lectures/index.json` と `lectures/Lxxx.json` を直接読みます。**push した時点で配信完了**です（アプリの再ビルドは不要）。

このファイルは、毎日 7:00・12:00・17:00（日本時間）に講義を1本作成する担当者（AI）向けの作業手順書です。毎回、最初に全文を読んでください。

**配信は1日3回で、枠によって形が違います**（詳しくは「3. 講義の形式」の最初の表）：朝7:00＝30分・確認問題5問／昼12:00＝15分・3問／夕17:00＝15分・3問。`curriculum.json` の各回に `slot`（am / noon / pm）・`minutes`・`questions` が入っています。

---

## 1. 目的と学習者

- 目的：学習者が **2027年度第1回 CFP資格審査試験（2027年6月13日・20日）で6課目すべてに一括合格**すること。
- 毎回、そのまま読んで学習できる**完成した講義**を1本届ける。学習計画や教材作成の提案で終わらせない。
- 学習者：FP2級取得済み、AFP認定研修修了済み、保険業界で約7年の実務経験。FP2級レベルの初歩的な説明だけでは不足。制度の背景・仕組み、数式、計算過程、具体例、比較表、例外まで学びたい。CFPの応用問題・難問に対応したい。
- 学習者には別に「毎月1課目」のメイン学習がある。この配信はそれとは独立に、6課目を幅広く先取りするもの。メイン学習の進み具合に合わせない。
- 配信しただけで学習者が理解・習得したとみなさない。

## 2. 1回の作業手順

1. `lectures/curriculum.json` を開き、**今回の担当回**を決める。
   - 日本時間の現在日時を `TZ=Asia/Tokyo date` で確認する。
   - `status` が `planned` で、配信日時（`date` の `am`=7:00 / `noon`=12:00 / `pm`=17:00）が現在以前のもののうち、いちばん古い回が担当回。
   - **前倒しの依頼**：`lectures/early.json`（回の id の配列。例 `["L002"]`）に id があれば、その回は配信日時より前でも担当回にする（学習者が「新しく配信して」と頼んだときに使う）。`early.json` に複数あれば先頭の1本だけ作る。作成後は `tools/publish.mjs` が `early.json` から外す。前倒しでも、`date` / `slot` / `subject` は curriculum.json の値のままにする（検証と一致させる）。
   - 配信漏れで該当が複数あるときは、古いほうから最大2回まで作る。該当が無ければ何も作らずに終了する。
   - 2027年5月1日以降は「5. 2027年5月以降」に従う。2027年6月20日より後は何も作らない。
2. 担当回の `slot` / `minutes` / `questions`（この回の長さと確認問題の数）と `subject` / `large` / `middle` / `small` / `also`（一緒に扱う中分類）/ `part`（「2/3」なら3回連続の2回目）/ `note`（前の回が残した申し送り）を確認する。
   - 分割回（`part` あり）の1回目を作るときは、**各回で扱う範囲の分け方**を決め、残りの回の `note` に書き込む（例：「2/3：損益通算の順序と不動産所得の負債利子」）。
   - 学習ガイドの中分類は最低限の範囲。その単元でCFP試験に必要な論点が中分類名から漏れていれば補う。
3. **課目をまたぐ重なりを確認する**。FP学習ガイドでは、同じ知識が複数の課目に出てくる（例：6つの係数・時間価値はライフ、目標リターンの算出は金融、生命保険の課税は保険・タックス・相続）。まず `lectures/index.json` と配信済みの講義の `middle` を見て、**すでに他の課目の回で扱った内容は導出や基本を繰り返さない**。その場合は「1分でわかる」で短くおさらいし、本文はその課目ならではの論点と応用に使う。逆に、後の回で扱う予定の内容を先取りして深入りしすぎない（`curriculum.json` で後続の回を確認する）。
4. 直近に配信した同じ課目の講義（`lectures/index.json` で確認）を2〜3本読み、**内容の重複を避け**、用語と水準をそろえる。
5. `lectures/feedback.json` を読む。学習者が間違えた問題・正答率の低い課目が記録されている。今回の単元に関係する誤答があれば、その論点の解説を厚くし、同じ論点を別の角度から問う確認問題を1問入れる。関係がなくても、同じ課目で誤答が続いている論点は、第4章（間違えやすい論点）の末尾に「前回までの復習」として短く取り上げてよい。
6. **一次資料をできる限り集める**（「4. 正確性のルール」）。数値・年齢・期限・税率・要件・計算式は、記憶で書かずに必ず資料で確かめる。1つの論点につき、制度の所管官庁のページと根拠条文（e-Gov）のように、可能なら2つ以上の一次資料で突き合わせる。
7. 講義 JSON `lectures/<id>.json` を作る（「3. 講義の形式」）。長い文章を JSON に直接書くと壊れやすいので、`tools/example_build_L001.py` のように Python で組み立てて出力するとよい。
8. **確認問題と本文を3回見直す**（短い回でも省略しない。誤りのない教材であることが最優先）。あわせて、問題ごとの**課目・分類を2回確認**して `classification` に記録する（後述「確認問題の課目・分類を確認する」）。見つけた問題はその場で直し、直したら同じ回の見直しをやり直す。
   - 1回目（解き直し）：作問時の考えを見ずに全問（朝5問・昼夕3問）を最初から解く。計算問題はコードで再計算し、誤りの選択肢の数値も再現する。答えが食い違ったら問題を直す。一致して初めて `verified_answer` を入れる。
   - 2回目（受験者の目で疑う）：各選択肢を1つずつ「別の読み方をすれば正しく（誤りに）ならないか」と疑う。正答が1つに決まるか、前提（端数処理・税金や手数料の扱い・期首か期末か・年度・年齢の基準日）が問題文に書かれているか、例外規定で正誤が変わらないか、問題文だけで解けるかを確かめる。
   - 3回目（資料との照合）：問題・解説・本文に出てくる数値・要件・期限・制度名を1つずつ拾い、一次資料の記載と照らし合わせる。法令基準日（2027年1月1日）時点の内容か、本文と解説で食い違いがないかを確かめる。照合できなかったものは `unconfirmed` に書き、その問題の `law_revision_flag` を `needs_check` にする。正答の根拠が確認できない問題は出題せず、作り直す。
9. `node tools/publish.mjs <id>` を実行する。エラーが出たら直して再実行する。
10. `git add -A && git commit -m "<id> <課目> <講義タイトル>" && git push origin lectures` で配信する。push に失敗したら原因を調べて再試行し、それでも配信できない場合は、その旨と理由を最終報告に明記する。
11. **スマホに通知を送る**（`PushNotification` ツールが使えるとき。使えない場合は省略してよい）。配信に成功したら、次の形式で1回だけ送る：
   `第◯回（課目名）「講義タイトル」を配信しました。約<minutes>分。 https://kota-mochizuki.github.io/cfp-study/#/lecture/<id>`
   配信できなかった（push 失敗・検証エラーが直せない）場合は、「第◯回を配信できませんでした：原因」と送る。担当回が無くて何も作らなかったときは送らない。講義の本文や問題の内容は通知に書かない。
12. 最終報告は3行程度：配信した回・タイトル・未確認事項の有無。

## 3. 講義の形式

### 枠ごとの形（朝30分／昼・夕15分）

| | 朝 7:00（`am`） | 昼 12:00（`noon`）・夕 17:00（`pm`） |
|---|---|---|
| 想定学習時間（`minutes`、確認問題を解く時間を含む） | 30（25〜40） | 15（12〜20） |
| 本文（体系図＋解説＋間違えやすい論点）の字数 | 5,000〜10,500字（目安 7,000〜9,000） | 2,500〜5,500字（目安 3,500〜4,500） |
| 確認問題 | 5問（計算要素があれば2問以上） | 3問（計算要素があれば1問以上） |
| 第3章の節 | 4節以上 | 3節以上（3〜4節） |
| `goals` / `plain` | 3つ以上 / 300〜900字 | 2つ以上 / 200〜700字 |
| 正解番号 | 3種類以上 | 2種類以上 |
| 向く内容 | 計算・総合・事例・仕組みの理解が要る論点 | 1テーマで完結する知識（要件・数値・例外・比較） |

- 想定学習時間には確認問題を解く時間（1問約2分）を含む。**朝は本文約20分＋問題約10分、昼・夕は本文約8分＋問題約6分**が目安。字数の上限・下限は `tools/publish.mjs` が検査する。
- 1回で収まらない範囲は、無理に詰め込まず次の回に回す（深さを削らない）。回す内容は、同じ中分類の後続の回の `note` に書く。
- 課目は毎回 `curriculum.json` で決まっている。同じ日の3回は必ず別の課目で、朝は6日で全課目に1回ずつ当たる。

### 合格までの効率を最大にする設計

- **得点に変わる形で書く**。各論点は「試験での問われ方 → 要件・数値・例外 → ひっかけ」の順に押さえ、背景説明は**なぜその仕組み・式になるのか**を理解するのに必要な分に絞る。丸暗記にしない。
- **確認問題が主役**。読んで終わりにせず、思い出す練習（確認問題）で定着させる。短い回は、本文を8分前後で終えて問題に移れる分量にする。
- **混同しやすいものは、必ず対で比べる**（似た制度・数値・期限・要件）。比較表を1つは入れる。
- **間隔をあけた再登場**：同じ課目の直近2〜3本の講義で扱った要件・数値のうち、混同しやすいものを1つ、確認問題の誤りの選択肢（比較・混同のひっかけ）に混ぜてよい。本文に書いた根拠のある内容に限り、正答は1つに決まるようにする。
- **出題実績を優先度に使う**。`tools/past_exam_stats.md` で件数の多い分野は、短い回でも応用寄りの問題を1問入れる。件数の少ない論点は、要点と例を1つに絞る。実績に無いことを「頻出」と書かない。
- **学習者の弱点を反映する**：`lectures/feedback.json` に誤答が増えている論点は、手順の5のとおり厚くする。

### 章立てとJSONの対応

| 章 | 内容 | JSON の項目 |
|---|---|---|
| 第1章 講義情報 | 配信日時・課目・タイトル・対象単元・想定学習時間・到達目標 | `id` `date` `slot` `subject` `title` `large` `middle` `minutes` `goals` |
| 第1章の末尾 1分でわかる | 小学生・中学生にも分かる言葉での「つまりどういうこと？」 | `plain` |
| 第2章 知識の体系図 | 大分類 → 中分類 → 個別論点 → 下位知識 の階層図 | `map` |
| 第3章 詳細な知識解説 | 節ごとの解説 | `sections`（`title` と `body`） |
| 第4章 間違えやすい論点 | 原則と例外、似た制度の違い、計算上の注意 | `traps` |
| 第5章 確認問題（朝5問・昼夕3問） | オリジナルの四肢択一 | `questions` |
| 第6章 解答と全選択肢の解説 | 正解、理由、誤りの理由、計算過程 | `questions` の解説項目 |
| 第7章 根拠資料 | 一次資料・URL・基準日・未確認事項 | `sources` `lawBaseDate` `verifiedOn` `unconfirmed` |

アプリでは、確認問題は学習者が回答するまで正答と解説が隠れます。

### 「1分でわかる：つまりどういうこと？」（`plain`、毎回必須）

講義の冒頭に出る、読むのに1分の説明です（**300〜900字**）。本文を読む前に全体像をつかむための欄で、専門知識がない人にも伝わることを目標にします。

- **小学生・中学生でも分かる言葉**で書く。専門用語は使わなくて済むなら使わず、使うときは直後にかみくだく（例：「**終価係数**＝いまのお金が将来何倍になるかの倍率」）。
- **たとえ話と小さな数字**を使う。身近な例（おこづかい、貯金、お店、給食費、学校のきまりなど）を1つ選び、数字は小さく切りのよいものにする。
- 構成：①この単元は一言でいうと何か → ②たとえ話か小さな具体例 → ③本文に出てくる用語・制度・係数を1行ずつ（表にしてよい）→ ④覚える手がかり（コツ・見分け方）→ ⑤「これはイメージ用で、試験では本文の正しい式・要件で解く」という注意。
- 本文の用語は、本文と**同じ名前**で出す（言いかえだけにしない）。覚えるべき名前を、平易な説明と結びつけるのが目的。
- **正確さを犠牲にしない**。たとえ話のために事実を曲げない。例外や数字が重要な論点は「くわしくは本文」と書いて流す。たとえ話は「たとえ」と分かるように書く。
- 3回の見直しの対象に含める。たとえ話が誤解を生まないか、数字は本文と一致しているかを確かめる。
- 書式：段落・太字・表のみ。見出しは使わない。

### アプリでの見え方（書き方に影響する）

学習者は「文章が多いと続かない」ため、アプリは**短く始めて、必要な所だけ深く読む**表示にしています。

- 最初に見えるのは、講義情報 →「1分でわかる」→ 第2章・第3章の**見出しだけ**（本文は閉じている）→ 第4章 → 確認問題。
- 学習者はまず確認問題を解き、**間違えた問題の `related_sections` の節だけ**を開いて読む。全文を通読する前提で書かない。

そのため：

- **各節は、その節だけ読んでも分かるように書く**。前の節を読んでいる前提の「上で述べたとおり」「前節の式」は使わず、必要な式や定義は短く再掲する。
- **節の見出し（`title`）は、中身が分かる具体的な言葉にする**（目次の役目をする）。「概要」「その他」は避け、「6つの係数 ― 式の意味と使い分け」のように書く。
- **第4章（`traps`）は必ず読まれる**。この単元で最も間違えやすい点と、数値・要件の要点は、第4章だけ読んでも押さえられるようにする。
- 確認問題の解説は、本文を読んでいなくても理解できるよう、根拠と計算過程を省かない。
- 本文の深さ・正確さは下げない。難問に必要な内容は、これまでどおり第3章に書く（読む量を減らすのは表示の工夫であって、内容を削ることではない）。

### 本文の水準

- 長さは上の「枠ごとの形」に従う（朝は本文5,000〜10,500字、昼・夕は2,500〜5,500字）。短い回でも、数値・要件・計算過程・例外といった**中身は削らず**、扱う範囲を絞って対応する。
- 各論点について、必要に応じて：定義／制度や指標の目的／仕組み／適用要件／数値・年齢・期限／計算式／計算過程／具体例／原則と例外／類似制度との比較／実務での利用場面。
- **なぜその仕組み・その式になるのか**を書く。用語の羅列や公式の丸暗記にしない。計算は、具体的な金額で途中経過を省かずに示す。
- 表と数式を使って整理する。基礎から応用へ段階的に進める。
- 学習者は保険実務の経験者。保険に関する初歩の説明は短くし、数理・税務・法律の精密さに字数を使う。
- 文体は「です・ます」。1文を短く。初めて出る専門用語は一度説明する。

### 本文で使える書き方（これ以外はアプリで表示が崩れる）

- 段落：空行で区切る。段落内の改行はそのまま改行になる
- 見出し：`### ` と `#### ` のみ（`#` `##` は不可）
- 太字：`**…**`
- 箇条書き：行頭 `- `（番号付きリスト `1. ` は不可。「- 手順1：」と書く）
- 表：`| A | B |` と `|---|---|` の形式。セルの中で `|` と改行は使えない
- 数式・階層図：``` で囲む（等幅でそのまま表示される）。LaTeX は不可。掛け算は `×`、割り算は `÷`、累乗は `^`
- リンク・画像・入れ子の箇条書き・斜体は不可

### 確認問題（朝5問・昼夕3問・すべてオリジナル）

- 四肢択一。難易度はCFP資格審査試験の応用〜難問（`difficulty` 3〜5）。
- 問題の中で、知識の正確な理解／適用要件／例外判断／計算／実務事例／複数条件の組合せ を組み合わせる（3問のときは3種類）。計算要素のある単元では、朝は計算問題を2問以上、昼・夕は1問以上。
- 問題文と選択肢に曖昧さを残さない。正答は必ず1つ。前提（端数処理、税金・手数料の扱い、期首・期末など）を問題文に書く。
- 計算問題の誤りの選択肢は、**典型的な間違い方をしたときに出る数値**にする（でたらめな数値にしない）。必要な係数や税率表は問題文に載せる。
- 正解番号は偏らせない（朝は3種類以上、昼・夕は2種類以上）。
- 公式過去問の本文は参照できず、転載もしない。使えるのは、`tools/past_exam_stats.md`（直近2回・600問の**出題分野別の件数と、境界で迷いやすい用語の課目別の件数**だけを載せた集計）に限る。出題実績を書くときは、この集計で確認できた範囲の事実だけにする（例：「直近2回の過去問では、6つの係数はライフ課目の問題に出ている」）。集計に無いことについて「頻出」「過去に出題」と書かない。件数は少ないので「出ていない＝出ない」とも書かない。

### 確認問題の課目・分類を確認する（2回以上、問題ごとに必須）

CFPは6課目の試験で、アプリの習熟度や学習レポートは各問の `subject`（課目）と中分類で集計されます。分類を誤ると、苦手の分析がずれます。問題ごとに次のとおり確認し、結果を講義 JSON の `classification` に記録してください。

1. **候補を探す（1回目）**：作問時に、`tools/guide_taxonomy.json`（FP学習ガイド2026年4月1日改定の大分類・中分類）を開き、その問題の知識が載っている**課目・大分類・中分類**を探す。講義の単元名で機械的に決めない。
   - 迷う用語（係数、住宅ローン、個人年金、利回りなど）は、`tools/past_exam_stats.md` の「2. 境界で迷いやすい用語」で、過去問ではどの課目に出ているかを裏付けに使う。ガイドの位置づけと食い違う場合は、`reason` に両方を書いて、**ガイドを優先**する（過去問は2回分・各課目100問と少ないため）。
2. **独立に判定し直す（2回目）**：問題が完成したら、講義の単元名を見ずに、**問題文と選択肢だけ**を読んで「この問題を解くために必要な知識は、どの課目のどの中分類にあたるか」を判定する。
3. **照合する**：1回目と2回目が一致しているか確認する。食い違ったら、次の基準で決める。
   - **問われていること（求めるもの・主題）**で決める。使う道具（例：税率）がどの課目の知識かではなく、「何を答えさせているか」で分類する。
   - **例外：6つの係数（終価・現価・年金終価・年金現価・減債基金・資本回収）を使う計算問題は、求めるものが金額でも利回りでも、ライフの「時間価値の考え方」に分類する。** 直近2回の過去問で、6つの係数を使う問題はすべてライフ課目に出題されている。金融に分類するのは、債券・株式などの商品の利回りや、目標リターンの考え方（係数を使わない知識・判断の問題）。
   - 複数の課目にまたがる場合は、解答を決める**主たる論点**の課目にする。ガイドで同じ知識が複数の課目に載っているときは、問題文で問われている側の課目を選ぶ。
   - 決めきれない境界の問題は、`reason` にその旨と理由を書く。
4. **記録する**：`classification` に、問題ごとに `first`（1回目：subject と middle）、`second`（2回目）、`final`（最終：subject・large・middle）、`reason`（判断の根拠、40字以上。食い違いがあれば決め方）を書く。
5. **反映する**：問題の `subject` / `category_large` / `category_middle` / `topic` を `final` と同じにする。**講義の課目と異なってよい**（例：金融の講義の問題が、ライフの中分類に分類されることがある）。大分類名・中分類名は `tools/guide_taxonomy.json` と**完全に一致**させる（`topic` は中分類名と同じ）。`tools/publish.mjs` が名称の一致と記録の有無を検査します。

## 4. 正確性のルール

- **法令基準日は 2027年1月1日**（日本FP協会 試験概要 https://www.jafp.or.jp/aim/cfp/cfp_exam/ で確認済み。月に1回程度、変更がないか見直す）。2027年1月1日時点で施行されている法令に基づいて書く。
- 公布日・施行日・適用開始日・経過措置を区別する。改正前の内容を現行制度として書かない。2027年1月1日までに施行される改正は改正後の内容で書き、必要なら「2026年分までは…」と旧制度を併記する。2027年1月2日以降に施行されるものは試験範囲外であることを明記する。
- 一次情報を優先する：日本FP協会の公開資料、国税庁、財務省、厚生労働省、日本年金機構、金融庁、法務省、国土交通省、総務省、e-Gov法令検索、日本取引所グループ、生命保険協会・日本損害保険協会 など。予備校・解説サイト・個人ブログは手がかりに使ってよいが、根拠としては引用しない。
- `sources` に載せるのは、**今回実際に開いて内容を確認したページだけ**。存在しない条文・資料・URL・過去問を作らない。URLは開けたものをそのまま書く。
- 確認できなかったことは推測で埋めず、`unconfirmed` に書く。本文でも断定しない。
- 公式テキストや会員限定の過去問は使えない前提。学習者に資料の提供を求めない。
- 年金額・保険料率・各種限度額など年度で変わる数値は、何年度の値かを明記する。
- 配信後に誤りに気づいたら、該当の講義 JSON を直して `node tools/publish.mjs <id>` を再実行し、push する（アプリは開いたときに最新版へ更新する）。訂正内容は講義の `unconfirmed` の先頭に「訂正（日付）：…」として残す。

## 5. 2027年5月以降

2027年4月30日の夕方の回（L605）で6課目の主要論点を一巡する。5月1日からは、同じ時刻（朝・昼・夕）に**総復習の講義**を作る。

- id は `R001` から連番。`date` と `slot` は配信日時。形式は通常の講義と同じ（章立て。長さと確認問題の数は枠ごと：朝5問・昼夕3問）。朝は複雑な計算・複合事例・時間配分の演習、昼・夕は重要論点の総復習と弱点対策に使う。
- 内容：重要論点の総復習／2027年1月1日基準での法令改正の確認／複雑な計算問題／複数課目にまたがる事例問題／`feedback.json` に基づく苦手分野の集中対策／本番を想定した時間配分（1課目50問120分、1問あたり約2分24秒）／直前期の重要数値・例外の確認。
- 6課目を均等に巡回する。試験1日目（6月13日）は金融・不動産・ライフ、2日目（6月20日）はリスク・タックス・相続。6月14日〜20日は2日目の3課目だけを扱う。
- **2027年6月20日の朝の回が最後**。それ以降は講義を作らず、「試験が終了したため配信を停止してよいか、利用者に確認が必要」と報告する。
